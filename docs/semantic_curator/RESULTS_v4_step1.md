# v4 第一步：實體／意圖與別名接入結果

日期：2026-10-25。分支：`feature/curator-v4`。僅本機實作與開發集驗證，未 push、合併、部署。

## 範圍與方法

沿用 v3 int8 模型與原有成員描述，不訓練、不增加 API 呼叫、不改寫任何資料 CSV。新增 `src/bot/curator_query.py`，接上既有 `grok_aliases.csv`：185 列包含 154 位成員、25 團與 6 列子團／舊團名；所有成員 ID 與團體對應均符合目錄。這是結構驗證，並非已外查每個暱稱或本名的正確性。

解析記錄實體、未消歧的同名候選、意圖、氣質／舞台／聲線面向與排除對象；明確別名改寫成標準名再送入既有向量檢索。完整人名優先，避免 HUENING KAI 同時命中 KAI；Jiwoo、Kim Dahyun 等同名需鄰近團名消歧，否則保留未解析狀態，不猜成某一人。常見英文詞需額外語境或大寫，英文短名有字界；歌曲書名號內的名稱不當成偶像別名。

目前規則基線：

- `similarity`：排除已解析的參照成員本人；團體參照排除該團；僅提到個人成員時優先其他團，其餘同團成員保留在後。不新增相似性證據或向量混合。
- `same_artist`：明確同團、原團作品、團內其他成員等請求優先原團。若同團內找相似成員，也排除參照本人。
- `related_music`：書名號中的作品相似請求，若未明說其他團，先保留原團；歌曲資料尚未接入。
- `general`：沒有可確定的參照意圖，沿用 v3 排序。單純提到平常聽誰，不等於要求同團。
- 明確「不要／排除／除了某團之外」綁定鄰近實體；不把不喜歡某首歌或「副歌以外」擴大成排除整團。
- 長相相似標記為本次不支援，不新增該面向檢索。氣質／舞台／聲線目前只記錄分面，尚未建立各分面的獨立索引或重排序。

Bot 的 `SemanticMemberRanker` 與離線 `v4-intent-aliases` 共用 `rank_ids`，沒有另外維護一套評估專用規則。缺少別名表時用目錄標準名字；原有模型缺漏／向量過期時退回 v1 的行為保留。建構 ranker 時不傳 parser 可重現 v3 行為。

## 三份 golden 為何修改

`tests/golden/analyze.json`、`line.json`、`mock_webhook.json` 是同一組對話經三個渠道的回覆快照，因此一個可見行為修正會反映在三份檔案。

共同變更只有「推薦 vocal 強的男團」這一題：

- 畫面成員一直是 SEVENTEEN THE8、EXO BAEKHYUN、SEVENTEEN HOSHI。
- 舊入口 ATEEZ《Ice On My Teeth》來自未顯示候選團體，違反「入口屬於畫面推薦團體」的規則。
- 修正後入口 SEVENTEEN《Darl+ing》符合畫面名單；成員、理由、按鈕及其餘對話逐字未變。

已用 `git show HEAD:tests/golden/<檔名>` 取得原版，驗證每份新檔都恰好等於原版只替換該一段入口文字及 URL，沒有其他差異。另在不改檔案的情況下以測試替身還原舊「從隱藏候選取團體」行為：新增 MV 回歸測試確實失敗，恢復修正後通過。故更新快照是在記錄已定義、獨立測試驗證的 MV 行為變更，並非以改快照掩蓋未解釋的失敗。這輪 v4 第一步沒有再次更新 golden。
